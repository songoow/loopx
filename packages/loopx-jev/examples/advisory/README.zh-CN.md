# D1–D6 显式调用示例

[English and commands](README.md)

这六组是合成示例，每组包含输入、目标依据和实际读取的本地证据。它们不冒充
上游 owner 正式导出的权威状态。安装可选包后，进入对应目录运行：

```bash
cd packages/loopx-jev/examples/advisory/D1-progress
loopx-jev assess --input input.json --basis basis.json \
  --config ../config.off.json --run-dir unused --report unused.json
```

默认关闭，不读取证据、账本或凭证，也不写报告。需要真实调用时，将配置复制到
忽略的私有目录，明确设定 `assist` 或 `shadow`、`allow_egress=true`，通过环境变量
提供凭证，用 `init-run` 创建有次数上限的新目录。完整命令见英文版。

| 方向 | 可以返回什么 | 不授予什么 |
| --- | --- | --- |
| D1 | 对齐关系、新增证据分开判断；等待状态单独保留 | 验收或结算权 |
| D2 | 复用、相关但不同、不相关、未知 | 新概念注册或更换 owner |
| D3 | 逐项核对声明与证据 | PR 通过或合并 |
| D4 | 保留全部候选、必读来源的建议顺序 | 隐藏矛盾材料或省略必读内容 |
| D5 | 已发现目录中的适用能力 | 安装、启用或工具权限 |
| D6 | 哪些已有方案新增信息，哪些重复探索 | 新建、执行或提交计划 |

`shadow` 只记录判断，不返回可消费的 `advice`；`assist` 在配置、输入和证据仍然
匹配时返回建议。关闭或卸载可选包后，原 LoopX 路径继续可用。输入文件中的 owner
及 revision 只是声明，精确文件哈希保证的是材料版本绑定，不是声明真实性。
该入口不会自动搜索全仓、运行正式 review、建立 Goal hook 或修改现有权威状态。

没有历史时，D1 新增证据必须为未知；没有实际读取的证据时不评估 D1。D3 缺引用
的声明即使模型说支持，也保留为证据不足。低于阈值的回答逐项变为未知，保留部分
覆盖，而不是把未知算成无问题。D7/D8 继续使用原有 capture/run 接缝。

耗时使用单调时钟以纳秒采样，展示单位不等于物理测量精度。报告区分准备、预留、
请求、校验、结果写入、owner 消费；HTTP 子进程再拆成准备、请求到响应头、正文
读取和封装。请求到响应头包含 DNS/TLS、网络、排队与推理，不能称为纯推理耗时。
父进程等待已包含子进程，不要再次累加。缓存重放的旧调用用量、耗时有明确标记；
独立重复实验必须使用独立且有预算的新运行目录。真实 Agent 执行和独立验收的
时间由实验驱动器另计，CLI 首事件不是首 token，单次耗时差异不能证明效率提升。

本轮扩展使用事先固定的样例标签、独立重复请求，并单独报告弃权及分歧。合成小
样例用于检查具体能力与限制，不等于真实任务分布上的准确率或产品效果证明。
